# Creating genome ↔ image datasets

This guide explains how a genes.jpg dataset is built, how to build one yourself, and what
the first dataset (`tol200m-mammals-smoke`) contains.

## 1. What a dataset is

A dataset pairs **one reference genome per species** with **many photographs of that
species**. Supervision is therefore species-level: the genome is not the genome of the
photographed individual. Every dataset is a directory with four tables and a manifest:

```
data/datasets/<name>/
  dataset.json                 provenance, selection parameters, counts (DatasetManifest)
  species.parquet / .csv       one row per species          (NCBI taxid, lineage, counts)
  genomes.parquet / .csv       one row per genome assembly  (accession, stats, md5, file)
  images.parquet / .csv        one row per image            (source, license, sha256, file)
  pairs.parquet  / .csv        image_id <-> assembly_accession
  genomes/<accession>/         <asm>_genomic.fna.gz, <asm>_assembly_report.txt, md5checksums.txt
  images/<taxid>/<image_id>.jpg
  logs/                        build.log, build_report.json, image_failures.jsonl
  README.md                    human summary generated by the builder
```

Species identity is the **NCBI Taxonomy ID**; names from image sources are kept only as
`original_label` / `source_names`. Field-by-field definitions are in
[dataset_schema.md](dataset_schema.md) and the machine-readable
[schemas/dataset.schema.json](../schemas/dataset.schema.json). All paths inside the tables
are relative to the dataset root, so a dataset directory can be moved as a unit.

`data/datasets` is a symlink to the shared disk (`/mnt/filesystem-s8/genes.jpg/datasets`
on the current machine) and is git-ignored; only configs, code and docs live in the repo.

## 2. Prerequisites

```bash
# Python environment (uv is in ~/.local/bin)
cd ~/genes.jpg && uv sync

# large artefacts live on the shared disk
mkdir -p /mnt/filesystem-s8/genes.jpg/datasets
ln -s /mnt/filesystem-s8/genes.jpg/datasets data/datasets
```

The builder talks to the **NCBI Datasets v2 REST API** (no key needed; set `NCBI_API_KEY`
for a higher rate limit) and downloads genomes from the NCBI FTP mirror over HTTPS.

### Source metadata: TreeOfLife-200M

Images are selected from the TreeOfLife-200M catalog
(`imageomics/TreeOfLife-200M` on Hugging Face, pinned to revision
`5f2dc493b3dc0e544438a04038ab15faa646b749`). The Hugging Face release contains **metadata
only**; image bytes are fetched from each record's `source_url` (78% of mammal images are on
iNaturalist's public S3 bucket). The builder reads a class-level subset so queries take
seconds instead of scanning 233 M rows:

```bash
# one-off, ~27 GB: catalog (16.8 GB) + provenance (10.3 GB)
.venv/bin/python - <<'EOF'
from huggingface_hub import hf_hub_download
for f in ["dataset/catalog.parquet", "dataset/metadata/provenance.parquet"]:
    hf_hub_download("imageomics/TreeOfLife-200M", f, repo_type="dataset",
                    revision="5f2dc493b3dc0e544438a04038ab15faa646b749",
                    local_dir="data/datasets/treeoflife-200m/raw")
EOF

# Mammalia subsets used by datasets.sources.treeoflife200m (4.8 M rows, ~0.5 GB)
.venv/bin/python - <<'EOF'
import duckdb
raw = "data/datasets/treeoflife-200m/raw/dataset"
duckdb.sql(f"COPY (SELECT * FROM '{raw}/catalog.parquet' WHERE class = 'Mammalia') "
           "TO 'data/datasets/treeoflife-200m/mammalia_catalog.parquet'")
duckdb.sql(f"COPY (SELECT p.* FROM '{raw}/metadata/provenance.parquet' p "
           f"JOIN 'data/datasets/treeoflife-200m/mammalia_catalog.parquet' c USING (uuid)) "
           "TO 'data/datasets/treeoflife-200m/mammalia_provenance.parquet'")
EOF
```

Two facts about these files that the code relies on: `catalog.source_url` is unique per
image and is the URL to fetch; `provenance.source_url` is occurrence-level (often a sibling
photo of the same observation) and is used **only** for `license_name`, `license_link` and
`copyright_owner`. The `species` column holds the epithet; `scientific_name` is the binomial.

### Genome snapshot (optional cross-check)

```bash
mkdir -p data/datasets/_ncbi
curl -o data/datasets/_ncbi/assembly_summary_vertebrate_mammalian_refseq.txt \
  https://ftp.ncbi.nlm.nih.gov/genomes/refseq/vertebrate_mammalian/assembly_summary.txt
```

The builder always chooses assemblies from the **live** API; if a snapshot path is given in
the config it compares the two and records any difference as a warning in `dataset.json`.

## 3. Writing a build config

A build is fully described by one JSON file in [configs/](../configs/). The smoke config:

```json
{
  "name": "tol200m-mammals-smoke",
  "version": "0.1.0",
  "description": "Smoke test: 5 mammal species ...",
  "root": "data/datasets/tol200m-mammals-smoke",
  "species": ["Vulpes vulpes", "Odocoileus virginianus", "Castor canadensis",
              "Tachyglossus aculeatus", "Dasypus novemcinctus"],
  "genomes": {
    "source": "ncbi_refseq",
    "assembly_summary_snapshot": "data/datasets/_ncbi/assembly_summary_vertebrate_mammalian_refseq.txt",
    "policy": "pick_best_assembly: reference > representative > other; Complete Genome > Chromosome > Scaffold > Contig; newest",
    "files": ["genomic.fna.gz", "assembly_report.txt", "md5checksums.txt"]
  },
  "images": {
    "source": "treeoflife-200m",
    "source_revision": "5f2dc493b3dc0e544438a04038ab15faa646b749",
    "per_species": 50,
    "seed": 0,
    "image_types": ["Citizen Science"],
    "exclude_basis_of_record": ["FOSSIL_SPECIMEN", "PRESERVED_SPECIMEN", "MATERIAL_SAMPLE"],
    "licenses": "cc_only",
    "max_per_observation": 1,
    "inat_size_variant": "large",
    "min_side": 224
  }
}
```

| Key | Meaning |
|---|---|
| `species` | Scientific names; each must resolve to one NCBI taxon of rank species (synonyms are accepted and recorded). Two names resolving to the same taxid abort the build. |
| `genomes.source` | Only `ncbi_refseq` for now: the species must have a current RefSeq assembly. |
| `genomes.assembly_summary_snapshot` | Optional NCBI `assembly_summary*.txt` used as a cross-check against the live API choice. |
| `images.source` | Key in `datasets.build.SOURCES` (currently `treeoflife-200m`). |
| `images.per_species` / `seed` | Target number of images per species and the seed of the deterministic sample. The source is asked for 1.3× candidates so dead URLs can be replaced. |
| `images.image_types` | TreeOfLife-200M `img_type` values to keep: `Citizen Science`, `Camera-trap`, `Museum Specimen: ...`, or `null` for untyped (EOL) rows. |
| `images.exclude_basis_of_record` | GBIF record bases to drop (fossils, preserved specimens, samples). |
| `images.licenses` | `cc_only` (any Creative Commons incl. BY-NC; drops NULL/other/all-rights-reserved), `permissive` (CC0, public domain, CC BY, CC BY-SA only) or `any`. |
| `images.max_per_observation` | Keep at most N photos per occurrence (`gbifID`) so one animal does not dominate. |
| `images.inat_size_variant` | For iNaturalist-hosted images: `large` (≤1024 px), `medium` (≤500 px) or `original`; the original URL is kept as a fallback. |
| `images.min_side` | Reject images whose shorter side is below this many pixels. |

## 4. Building

```bash
# 1. plan only: resolves species, picks assemblies, counts candidates, downloads nothing
.venv/bin/genes-datasets build configs/tol200m-mammals-smoke.json --dry-run

# 2. build (idempotent; safe to re-run after an interruption)
.venv/bin/genes-datasets build configs/tol200m-mammals-smoke.json

# 3. check and inspect
.venv/bin/genes-datasets validate data/datasets/tol200m-mammals-smoke --check-hashes
.venv/bin/genes-datasets info     data/datasets/tol200m-mammals-smoke
```

What `build` does, in order:

1. **Species** — `ncbi.resolve_taxon` turns each name into a `TaxonInfo` (taxid, accepted
   name, common name, full lineage). A subspecies hit is lifted to its species taxid with a
   warning.
2. **Genomes** — `ncbi.list_refseq_assemblies(species_taxid)` lists current RefSeq
   assemblies; `pick_best_assembly` applies the policy above; `download_genome` fetches the
   gzipped FASTA, assembly report and `md5checksums.txt`, resumes partial files, verifies the
   MD5 published by NCBI, counts FASTA records and fills a `GenomeRecord`. Files already
   present and verified are reused.
3. **Images** — the source's `select()` runs one DuckDB query over the catalog +
   provenance parquets with all filters, dedupes per observation and orders candidates by a
   seeded hash; `images.download_images` fetches them concurrently (≤4 requests/s per host,
   retries with back-off, atomic writes), decodes each file with PIL, rejects non-images,
   truncated or too-small files, and records sha256/size/dimensions. Failures are topped up
   from the remaining candidates and logged to `logs/image_failures.jsonl`.
4. **Pairs** — one `PairRecord` per image to its species' assembly (`pairing =
   species_reference`).
5. **Tables + manifest** — parquet and CSV for each table; `dataset.json` records the
   source revision, snapshot, the full config, effective filters, assembly choices, download
   statistics and warnings; a `README.md` with the per-species table and license breakdown is
   generated.
6. **Validation** — `validate_dataset(check_hashes=True)` re-checks every row against the
   schema, referential integrity, file presence, sizes and hashes, and the manifest counts.
   The build fails if anything is reported.

Re-running at the same root reuses verified genomes and images, rewrites the tables and
removes files under `images/` that the new tables no longer reference.

## 5. The generated dataset: `tol200m-mammals-smoke`

Built 2026-10-03 from the config above in 143 s (genomes were pre-fetched; the time is
MD5/FASTA verification of 4 GB plus 250 image downloads). Location:
`data/datasets/tol200m-mammals-smoke/` (= `/mnt/filesystem-s8/genes.jpg/datasets/tol200m-mammals-smoke/`).

| Species | TaxID | Order | RefSeq assembly | Level | Genome (bp) | Sequences | FASTA (gz) | Images |
|---|---|---|---|---|---|---|---|---|
| *Vulpes vulpes* (red fox) | 9627 | Carnivora | GCF_048418805.1 VulVul3 | Chromosome | 2,395,584,468 | 289 | 754 MB | 50 |
| *Odocoileus virginianus* (white-tailed deer) | 9874 | Artiodactyla | GCF_023699985.2 Ovbor_1.2 | Chromosome | 2,423,246,854 | 481 | 770 MB | 50 |
| *Castor canadensis* (American beaver) | 51338 | Rodentia | GCF_047511655.1 mCasCan1.hap1v2 | Chromosome | 2,814,832,999 | 181 | 860 MB | 50 |
| *Tachyglossus aculeatus* (short-beaked echidna) | 9261 | Monotremata | GCF_015852505.1 mTacAcu1.pri | Chromosome | 2,213,004,214 | 310 | 639 MB | 50 |
| *Dasypus novemcinctus* (nine-banded armadillo) | 9361 | Cingulata | GCF_030445035.2 mDasNov1.1.hap2 | Chromosome | 3,610,534,858 | 546 | 1,140 MB | 50 |

Totals: 5 species, 5 genomes (4.16 GB, all "reference genome", chromosome-level, MD5-verified
against NCBI), 250 images (95.7 MB; 462–1024 px; 0 failed downloads), 250 pairs.

Image provenance: 219 iNaturalist, 22 Atlas of Living Australia, 9 observation.org, all
`Citizen Science` records of `HUMAN_OBSERVATION` basis, one photo per observation.
Licenses: 187 CC BY-NC 4.0, 46 CC BY 4.0, 10 CC BY-NC-ND 4.0, 5 CC0 1.0, 1 CC BY-SA 4.0,
1 CC BY-NC-SA 4.0 — each image row carries `license`, `license_url`, `rights_holder` and
`publisher`. The species were chosen (see [survey_mammals.md](survey_mammals.md)) to span five
mammalian orders, to have chromosome-level RefSeq reference assemblies and ≥24 k
citizen-science photos each, so the pipeline is exercised on visually distinct animals.

Why these choices for a smoke test: `Citizen Science` only (no museum skins/skulls, no
camera-trap frame bursts); `cc_only` keeps the sample large while recording each license so a
stricter policy can be applied later by filtering `images.license`; `large` keeps files at
≤1024 px (≈0.4 MB) instead of multi-MB originals.

What this dataset is **not**: no train/val/test split is assigned (`species.split` is empty —
the intended protocol is species-held-out), label noise has not been quantified (iNaturalist
mammal photos can show tracks, scat or remains), and five species cannot support model
training; it exists to prove the pipeline end to end.

## 6. Scaling up

- **All RefSeq mammals.** 250 of the 270 RefSeq mammal species have TreeOfLife-200M images
  under exact binomial match (2.02 M citizen-science + 165 k camera-trap images); 11–14 more
  are recoverable with NCBI synonyms. Add a `species` list (or a source option to take every
  matched species) and raise `per_species`. At ≈0.4 MB per `large` image, 1,000 images per
  species is ≈100 GB; genomes are ≈0.8 GB each.
- **Taxid-based matching.** Today the source matches `scientific_name` strings (GBIF
  backbone) against the config name and its NCBI accepted name; resolving catalog names to
  taxids with synonym handling is the next step.
- **Splits.** Assign `species.split` species-held-out (then genus/family-held-out); keep
  `observation_id` grouping if finer splits are ever used.
- **Other sources.** Implement `datasets.sources.base.ImageSource` (`select`, `source_info`,
  `selection_params`) and register it in `datasets.build.SOURCES`; BioTrove (iNaturalist-only,
  256 RefSeq mammal species) is the natural second source.
- **Licensing.** 77% of TreeOfLife-200M mammal images are CC BY-NC; commercial use needs the
  `permissive` policy and a review of iNaturalist's terms of use.
